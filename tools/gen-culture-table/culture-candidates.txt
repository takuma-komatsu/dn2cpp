# The named-culture table's CANDIDATE SET — the input to gen-culture-table.cs.
#
# WHY THIS FILE EXISTS AT ALL. The rule that earns a culture a row is a property
# of the HOST, not of the culture: a culture is a candidate iff it can be a host
# locale on a platform dn2cpp targets — the UTF-8 entries of macOS `locale -a`
# mapped through the same POSIX-id rewrite dn2cpp_pal_locale_from_posix_id
# applies, unioned with the common glibc locale set, plus every neutral parent
# (a bare `LANG=de` produces one). That rule reads the GENERATING MACHINE, so a
# generator that re-derived it would emit a different table on every developer's
# box — and the table would then be a fact about whoever last ran it. The
# resolved set is therefore frozen here and the generator reads it, so
# regenerating changes VALUES (the oracle's ICU) and never MEMBERSHIP.
#
# TO EXTEND IT, run the rule by hand and diff:
#
#   locale -a | grep -i 'utf-8$' | sed 's/\..*//' | tr '_' '-' | sort -u
#
# then add the missing names and their neutral parents below, keeping the file
# sorted ordinal-ascending (the generator emits rows in this file's order, and
# the table's own comment says a linear scan is deliberate — order is
# readability, not a lookup invariant). A name real .NET cannot materialize, or
# one whose NumberFormatInfo the modeled row shape cannot represent, is REFUSED
# by the generator with a printed reason and simply gets no row: it keeps the
# honest name-preserving fallback (invariant symbols under the requested name)
# rather than a row that would be wrong.
#
# 160 names, including the Indian numbering family — representable only since the
# modeled NumberFormatInfo carries .NET's NumberGroupSizes array rather than a
# single uniform digit-group size.
